## 1 Условия и классификация данных

### 1.1 Порядок проверки условий

Сначала выполняется проверка диапазонов с помощью конструкции 
if / elif / else. Результат должен лежать в пределах от 0 до 100,
число пропусков – от 0 до 5.
При нарушении любого из условий возвращается сообщение об ошибке, 
и дальнейшая классификация не выполняется (ранний выход из функции evaluate).

Уровень определяется цепочкой условий в порядке убывания порога: 
результат не менее 90 даёт уровень «отличный»,
иначе не менее 75 – «хороший», иначе не менее 60 – «удовлетворительный»,
иначе – «недостаточный». Каждая следующая ветвь проверяется только тогда,
когда предыдущая не сработала, 
поэтому в ветвях достаточно указывать только нижнюю границу диапазона.
Если проверять пороги в обратном порядке (сначала не менее 60), 
то ветви для 75 и 90 оказались бы недостижимыми, 
так как любой результат от 60 и выше попадал бы в первую ветвь.

Если пропущено более трёх занятий, индекс уровня уменьшается на единицу,
но только когда он больше нуля, поэтому ниже уровня «недостаточный»
результат не опускается. Ровно три пропуска не приводят к снижению,
так как условие строгое.

Тип работы разбирается конструкцией match / case с тремя известными 
значениями и ветвью case _ для неизвестного значения. 
Неизвестный тип не прерывает обработку: 
выводится пояснение «неизвестный тип работы»,
а уровень определяется как обычно.

При выбранном порядке проверок недостижимых ветвей в пределах допустимых данных нет. Недостижимой для функции evaluate является только ситуация, когда в классификацию попадает результат вне диапазона от 0 до 100: такие данные отсекаются проверкой диапазонов. Отдельно следует отметить, что при некорректном результате сообщение о пропусках не формируется, так как вторая проверка находится в ветви elif и при срабатывании первой не выполняется.

## 2 Циклы и базовые алгоритмические схемы

### 2.1 Алгоритмы и псевдокод

Для набора измерений [12, 15, 11, 18, 18, 9, 21, 15, 7, 18] за один
проход вычисляются сумма, минимум, максимум и количество чётных значений.
Среднее арифметическое становится известно только после этого прохода,
поэтому подсчёт значений выше среднего выполняется вторым проходом. 
Получены следующие значения: сумма 144, минимум 7, максимум 21,
чётных значений 4, среднее 14,4, значений выше среднего 6.

Алгоритм 1 – Статистики за один проход

```text
ВХОД: список values
ЕСЛИ values пуст, ТО вернуть «нет данных»
total ← 0; min ← values[0]; max ← values[0]; even ← 0
ДЛЯ КАЖДОГО v ИЗ values:
    total ← total + v
    ЕСЛИ v < min, ТО min ← v
    ЕСЛИ v > max, ТО max ← v
    ЕСЛИ v mod 2 = 0, ТО even ← even + 1
вернуть total, min, max, even
```

Линейный поиск возвращает индекс первого вхождения или 
значение –1 и считает число сравнений. 
Для числа 18 найден индекс 3 за 4 сравнения,
для отсутствующего числа 100 получено значение –1 за 10 сравнений.

Алгоритм 2 – Проверка простоты числа n

```text
ВХОД: целое n > 0
ЕСЛИ n < 2, ТО вернуть «не простое»
d ← 2
ПОКА d · d ≤ n:
    ЕСЛИ n mod d = 0, ТО вернуть «не простое»
    d ← d + 1
вернуть «простое»
```

Алгоритм 3 – Бинарный поиск в отсортированном списке a

```text
ВХОД: отсортированный список a, искомое x
low ← 0; high ← длина(a) – 1; сравнений ← 0
ПОКА low ≤ high:
    mid ← (low + high) div 2; сравнений ← сравнений + 1
    ЕСЛИ a[mid] = x, ТО вернуть mid
    ИНАЧЕ ЕСЛИ a[mid] < x, ТО low ← mid + 1
    ИНАЧЕ high ← mid – 1
вернуть –1
```

### 2.3 Обоснование границы по квадратному корню

Пусть число n составное, то есть n = a · b, где 1 < a ≤ b.
Тогда a² ≤ a · b = n, откуда a ≤ √n. 
Следовательно, у любого составного числа есть делитель в
промежутке от 2 до √n включительно, и если такой делитель не найден,
число простое. Условие d · d ≤ n эквивалентно d ≤ √n, 
но вычисляется в целых числах без ошибок округления,
которые возможны при работе с вещественным квадратным корнем.
Для числа 7919 проверено 87 делителей вместо 7917 при полном переборе.
Следует учитывать, что сложность O(√n) выражена через величину числа,
а не через длину его записи:
относительно числа разрядов k она растёт как O(2^(k/2)).

### 2.4 Сравнение линейного и бинарного поиска

Обе стратегии запущены на одинаковых наборах из 10, 100 и 1000
различных чисел. Линейный поиск выполняется в исходном порядке,
бинарный – в списке, отсортированном собственной сортировкой выбором.
Одна итерация бинарного поиска считается одним трёхсторонним сравнением.
Для среднего значения искались все элементы набора, 
для худшего случая – отсутствующее число. 
Основной результат – число сравнений – приведён в таблице 4.

Таблица 4 – Число сравнений при поиске

| n    | Линейный, среднее | Линейный, худший | Бинарный, среднее | Бинарный, худший | Сортировка выбором |
|------|-------------------|------------------|-------------------|------------------|--------------------|
| 10   | 5,50              | 10               | 2,90              | 4                | 45                 |
| 100  | 50,50             | 100              | 5,80              | 7                | 4950               |
| 1000 | 500,50            | 1000             | 8,99              | 10               | 499500             |

Число сравнений линейного поиска растёт пропорционально n,
а бинарного – пропорционально log n: 
при n = 1000 в среднем требуется 500,50 и 8,99 сравнений соответственно.
Однако бинарному поиску необходим отсортированный список.
Стоимость сортировки выбором для 1000 элементов
составляет 499500 сравнений, поэтому сортировка окупается лишь
при примерно 1016 и более последовательных поисков в одних и тех же данных.

### 3.2 Обоснование выбора коллекций

- множество подходит для хранения уникальных значений, потому что устроено на основе хеш-таблицы: повторное добавление того же элемента не меняет множества, а проверка принадлежности и операции пересечения выполняются без перебора,
- кортеж можно использовать как ключ словаря, потому что он неизменяем и хешируем: его хеш вычисляется по хешам элементов и не меняется в течение жизни объекта,
- список нельзя использовать как ключ словаря, потому что он изменяем и не имеет хеша (попытка приводит к ошибке TypeError); если бы содержимое ключа могло меняться, изменился бы его хеш, и запись стала бы недоступной в своей корзине,
- словарь предпочтительнее списка для частого поиска результата по составному ключу, потому что поиск в списке кортежей требует перебора всех m записей за O(m), а доступ по ключу (студент, работа) выполняется в среднем за O(1).

### 4.3 Изменяемое значение по умолчанию

В функции add_result_buggy(value, results=[]) список по
умолчанию создаётся один раз в момент выполнения оператора
def и сохраняется в атрибуте \_\_defaults__ объекта функции.
Все вызовы без второго аргумента получают один и тот же объект 
и дополняют его. Поэтому после вызовов add_result_buggy(1) 
и add_result_buggy(2) обе функции вернули один и тот же 
список [1, 2], а __defaults__ принял вид ([1, 2],).
В исправленной версии значением по умолчанию служит None, 
а новый список создаётся внутри тела функции при каждом вызове;
вызовы add_result(1) и add_result(2) вернули [1] и [2].

### 4.4 Функции как аргументы и замыкания

Функция apply_to_results принимает другую функцию и последовательность результатов и
возвращает новый список. Ей переданы именованная функция percent и лямбда-выражение lambda s: s + 5.
Фабрика make_threshold_checker(threshold) возвращает вложенную функцию,
которая запоминает значение threshold в замыкании. Созданы две независимые проверки: 
с порогом 60 для набора [55, 78, 91] получено [False, True, True], с порогом 90 – [False, False, True]. В ячейках замыкания (__closure__) хранятся числа 60 и 90, то есть каждая созданная функция сохраняет собственное значение порога, а не общее.

## 5 Анализатор учебных результатов

### 5.1 Декомпозиция и принятые правила

Программа разделена на функции трёх уровней. 
Базовые функции mean, minimum и maximum работают со списком чисел.
Функции classify и student_summary описывают одного студента.
Функции group_summary, find_top_students
и format_report работают с группой.
Каждая функция решает одну задачу и 
использует результаты функций нижнего уровня,
поэтому любую из них можно проверить отдельно.

Заранее выбраны следующие правила. 
Студент с пустым списком результатов получает категорию «нет данных», 
а его среднее, минимум и максимум равны None. 
Такой студент не участвует в общей статистике,
рейтинге и выборе лидеров, но учитывается в
счётчике категории «нет данных».
Рейтинг строится по среднему результату по убыванию, 
а при равенстве – по имени по возрастанию. 
Общий средний результат группы вычисляется
по всем отдельным результатам. 
Исходный словарь не изменяется, что проверяется в каждом сценарии.

### 5.4 Сложность построения общей статистики

Пусть в группе S студентов и всего N результатов. 
Для каждого студента среднее, 
минимум и максимум вычисляются отдельными проходами по его списку, 
а общая сумма накапливается при том же обходе,
поэтому построение статистики требует O(N + S) операций времени 
и O(S) дополнительной памяти под сводки. 
Поиск лидеров и подсчёт категорий линейны по тем же величинам.
Рейтинг строится сортировкой вставками и в худшем случае требует
O(S²) сравнений, что допустимо для учебной группы; 
при росте числа студентов её можно заменить сортировкой со сложностью O(S log S).
